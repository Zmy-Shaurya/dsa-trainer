## Which pattern?

| Clue in the problem | Try |
|---|---|
| Sorted input, pair or triple with a sum | Two pointers |
| Longest or shortest contiguous range | Sliding window |
| Many range-sum queries | Prefix sums |
| Look up the complement of what you have seen | Hash map |
| Sorted, or a yes/no check over a numeric range | Binary search |
| Next greater or smaller element | Monotonic stack |
| Max or min of every window | Monotonic deque |
| k largest, k smallest, k most frequent | Heap of size k |
| Running median | Two heaps |
| Shortest path, unweighted | BFS |
| Shortest path, weighted, non-negative | Dijkstra |
| Connected regions in a grid | Flood fill (DFS or BFS) |
| Groups that merge over time | Union-find |
| Tasks with prerequisites | Topological sort |
| Generate every selection or ordering | Backtracking |
| Optimal answer built from smaller answers | Dynamic programming |
| Cycle in a linked structure | Fast and slow pointers |
| Overlapping ranges | Sort by start, merge |
| Pairs cancel, parity, single value | XOR and bit tricks |
| Prefix queries over many words | Trie |

## Before coding

1. Restate the input, output and limits.
2. Say the brute force and its cost.
3. Name the pattern that removes the wasted work.
4. Test on an empty input, one element, and duplicates.
